# 评测时间语义与双门禁

本规格解决系统评测把自然时间流逝误判为代码回归的问题，同时保留对真实停更、采集失效和数据过期的运营告警。

## 已确认决策

- PR CI 与运营时效使用两类门禁，不共享同一种通过语义。
- PR CI 在基线的同一参考时刻重算，所有维度仍参与严格比较。
- 运营门禁按当前时间评测，复用现有系统分 60、24 小时 critical、72 小时持续硬告警和 120 小时刷新冷却期。
- 报告升级为 schema v2，显式记录 `evaluationAsOf` 和 `gateMode`，兼容读取 schema v1。
- Monitor 使用版本化 `evaluationAsOf` 判断数据水位，不再把 checkout 后的文件 mtime 当作权威证据。
- 运营失败先记录证据和单一健康事件，再最多触发一次有界 incremental refresh，最后使门禁失败。
- 当前暂停的 schedule 不在本规格中恢复；启用频率是独立运营决策。

本规格扩展 `2026-07-12-autonomous-quality-operations` 的评测闭环。若两者对时间语义或回归比较的描述冲突，以本规格为准；“真实证据增长才允许分数增长”的原则保持不变。
